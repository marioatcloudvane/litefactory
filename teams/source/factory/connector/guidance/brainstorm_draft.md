Use brainstorm_draft when the owner says the brainstorm is ready, or asks for tasks or drafts. Say back in one sentence what you will ask for, and pass anything the owner wants the drafts to keep in mind as the short note. It starts one paid read-only run that reads the whole kept brainstorm and turns it into one to five task drafts. It runs under the owner's standing repository:brainstorm consent; there is no further confirmation. Nothing is created and nothing starts from drafts.

Use a fresh request_key for each request. After a lost reply, retry with the same request_key and the same note; you get the same run, not a second one. The reply is the run and its state. It is listed with the other questions in brainstorm_scans, so you find it again after a reconnect. Check it with brainstorm_scan_get and keep talking with the owner while it runs. When it is answered, read the drafts with brainstorm_drafts_get.

Asking for drafts again replaces the earlier drafts that were not used yet. Before you ask again, keep every new answer or decision in the brainstorm first, so the new drafts can use it. A closed brainstorm cannot make new drafts. If the reply says the installed team has no drafting skill yet, tell the owner plainly that a newer team version must be installed first.
