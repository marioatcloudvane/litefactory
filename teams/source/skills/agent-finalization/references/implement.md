# Implement serialization

Reference exact authorized frozen story keys and retained engineering snapshot/check
IDs. Capture complete deterministic bytes and actual executed check facts while work
is available; never invent a passed flag or execution-time digest. Separated workflow
uses engineering_complete and rejects acceptance assessments. Legacy verified keeps
complete engineering and assessment obligations. Completed requires all selected
engineering obligations and required aggregate proof bound to final bytes and exact
frozen revisions. Aggregate-only recovery reuses earlier story proof without adding
story contributions. Incomplete/blocked exits require no invented successful proof.
Questions are disallowed. Validate and acceptance remain separate factory decisions.

Executable application-v1 examples (synthetic offline identities):
- [completed](examples/implement-completed.json)
- [incomplete](examples/implement-incomplete.json)
- [blocked](examples/implement-blocked.json)
- [revision-checked update](examples/implement-update.json)
- [disallowed question](examples/invalid-spike-question.json); questions reject in this mode too.

Use the separate checkpoint descriptor for scoped story evidence. The shared result
adapter accepts the declared aggregate engineering/capture shape, retaining actual
execution facts against complete final bytes. Capture alone does not satisfy final
output; reference its snapshot/check IDs in payload.implement.aggregate_checks.
Preflight, submit and post-exit enforcement resolve retained aggregate/checkpoints
and current worktree bytes. Missing resolvers/evidence never relax required proof.
