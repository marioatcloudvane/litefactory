# Validate serialization

Use authorized retained snapshot/check references for complete criterion and code,
architecture and plan findings. This mode cannot capture implementation bytes or
execute checks. Completed means a complete assessment: findings can be unmet or
unverified, and completion does not grant acceptance. Preserve prior assessments;
updates prepare a new result revision. Incomplete/blocked retain actual findings and
explain missing evidence or the obstruction. Questions are disallowed.

Executable application-v1 examples (synthetic offline identities):
- [completed](examples/validate-completed.json)
- [incomplete](examples/validate-incomplete.json)
- [blocked](examples/validate-blocked.json)
- [revision-checked update](examples/validate-update.json)
- [disallowed question](examples/invalid-spike-question.json); questions reject in this mode too.

The declared structured terminal contributions envelope remains supported. No shell,
edits, new checks, capture or delegation are permitted. Already permitted live
communication is optional: identical terminal/live findings reconcile; conflicting
findings reject before new terminal decisions. Return complete frozen scope even
when earlier live checkpoints cover part of it. Historical reads grant no writes.
