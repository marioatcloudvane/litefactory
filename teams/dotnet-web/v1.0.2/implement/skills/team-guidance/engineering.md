# Repository engineering
Read repository instructions and CI before editing. Use existing component and test
patterns, explicit targets and the captured stack recipes. Keep changes within the
one story. Run affected test projects completely; never report unexecuted checks.
Use Release analyzer builds and format verification. Preserve failed/cancelled
outcomes and retain command evidence. Do not fall back to another language stack.
Validate reviews retained evidence read-only: no execution, edits or commissioned
checks. Only the factory owns gates, approvals, merge and publication. Profiles
cannot change sandbox, credentials, network authority or global factory settings.
Prepare SDKs, workloads and browsers through the operator, never by automatic
installation. Package checks are not proof of a working application or live provider.
