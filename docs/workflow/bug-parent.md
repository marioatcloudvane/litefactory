# Bug parent composition

`bug.dot` pins the analyst, fixer, result resources and `bug_tests.dot` in one captured package. Factory registries admit its exact topology and roles. The seven domain handlers retain their authority: parent edges select a next activity but never approve a remedy, spend a budget, establish check success or confirm remote delivery.

The eight analysis passes and three repair reservations are lifetime ledgers. One `attempt` node receives initial repair, ordinary test failure and in-scope PR feedback. Its fourth dispatch is an exhaustion probe. The parent permits up to six test/PR visits in an execution envelope: three repair generations plus three technical freshness observations. Merge has four visits, allowing freshness refusals before a confirmed integration. These are finite technical ceilings, not permission to retry a known flaky check. Ceiling exhaustion stops with a retained failure; owner continuations preserve all lifetime usage.

Source/recipe/target staleness returns to the test activity, whose binding guards still require a valid completed repair. Owner questions, exact analysis review, exact delivery review, child wait and pending remote effects have distinct retained dispositions. Clarification returns through the PR activity without a repair reservation. Unknown outcomes fail validation. Infrastructure recovery requires a recorded authenticated resolution of a consumed blocked child and confirmed cleanup, with no unreliable phase; it never spends a repair slot.

An allocated authenticated owner wait can atomically end its current execution envelope and create one successor at the factory-selected checkpoint. The original graph history remains terminal. Replays compare the retained reply identity, author and bytes; they recover the original successor. They cannot choose a node or reset counters. Review changes are retained as owner context and revoke current review applicability; fresh analysis requires the same existing approval gate.

Cancellation is durable before new domain dispatch. It blocks new analysis, repair, child and delivery claims, reaches child command cancellation flags, and preserves unknown cleanup and remote effects. Failure publications retain either an actual failed attempt or an explicit pre-dispatch event. Ordinary blocked/exhausted notices retain their successful domain source. One immutable report identity survives uncertain publication, and confirmation requires the exact retained body and task.

Lifecycle completion is separate from graph status. It requires independently confirmed closure, the authorized integration chain and both owner gates, with no outstanding process, effect or required-report obligation. An already closed issue or a successful terminal graph cannot create missing authority.

New analysis may include exact `boundaries.allowed_paths` and `boundaries.excluded_paths` as typed detail of its bounded remedy. The same analysis digest and existing owner approval bind those fields. Default source observation compares actual immutable changed files against those boundaries; it does not claim blanket semantic proof. The fixer remains responsible for semantic remedy compliance and full criterion coverage. Historical scopes without concrete bounds remain indeterminate and need a new analysis revision if repair is required.
