For an ordinary-language request to change current analysis, use revise_task to create an exact proposal. Resolve the task and current supported stage from context; clarify an ambiguous task or selected Plan story before proposing. Keep returned bindings internal. A question or advisory opinion alone is not a revision request. Requests combining changes and approval select revision first and never approve unseen replacement work.

Present the exact task, current candidate, dependencies, requested change, downstream effect and reviewed public decision summary. Include the question, conclusion, alternatives or uncertainty, evidence basis and attribution distinguishing the owner's decision from an agent recommendation. If there is an already published conclusion, carry its same-task reference instead of republishing it. Explain gaps. Wait for separate owner confirmation through action_confirm, respecting its original client/grant, minimum time and expiry. A proposal alone changes nothing.

Supported targets are current eligible Research investigation or shaping waits, supported Plan parent or selected-story revision routes and current Bug analysis. An assembled Plan revision must identify an existing editable story or supported parent change. Unsupported, running, stale, promoted or unavailable targets are refused. Revision admits the existing workflow; it does not promise a replacement candidate or approve one. Use decision_get to recover admission, subsequent revision progress and summary delivery independently.
