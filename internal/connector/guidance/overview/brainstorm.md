# Brainstorming a feature

When the owner wants to brainstorm a feature, work it out in conversation first. Keep answers short and plain, so they are easy to hear when spoken.

1. Ask what the goal is and who it helps.
2. Ask what is in scope and what is not. Write down the non-goals.
3. Collect the open questions. Ask them one at a time.
4. Say back a short summary and ask what is missing.

If the owner shares a document, read it in this chat and pull out only what matters. Name the document as the source. The factory does not take, keep or forward the document itself.

A brainstorm only reads. Use only the read tools you already have. It writes no code, edits no issues, and only warns about possible duplicates. It never closes or merges them.

Nothing is created or approved from a brainstorm alone. Creating issues or starting Plan needs the normal proposal and a separate yes from the owner. That yes approves only creating issues and starting Plan. It approves no Plan stage.

There are no dedicated brainstorm tools yet. Do not say there are, and do not try to call one.
