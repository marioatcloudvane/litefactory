Creating tasks from brainstorm drafts uses two owner actions through the normal proposal tools: brainstorm_create_tasks and brainstorm_task_recreate. Use brainstorm_tasks_get to read how a batch of new tasks is doing.

To create tasks, propose brainstorm_create_tasks with action_propose and the arguments brainstorm, draft_set and drafts. drafts is the comma-separated list of the keys of the drafts the owner kept, in the order read; leave out every dropped draft. Read the proposal back in plain words: the titles that become issues, that each issue then starts Plan from its draft's brief, and what it costs when that is known. Say that the yes approves only creating these issues and starting Plan. It approves no Plan stage; every Plan stage still waits for its own owner approval. Then wait. Only when the owner says yes in a new message, confirm with action_confirm, at or after confirm_not_before and before the proposal expires. Never confirm on your own, never in the same message as the proposal, and never treat a yes given before the proposal as consent. If drafts of this set already have tasks, the proposal says it continues that batch: only unfinished drafts go on and no draft gets a second issue.

The reply to the yes names the batch. Read it with brainstorm_tasks_get and tell the owner one plain outcome per draft, with the issue number when known. A draft counts as started only after its brief is ready and Plan's first agent runs; until then say it is created and still starting. Created but not started means the issue stays and Plan did not start; the owner can ask you to propose the same drafts again, which only retries the start, or type /plan on the issue. Not created means the factory knows the issue was not made; proposing the same drafts again tries only those. Pending means it was not tried yet, for example because the batch stopped. The factory also sends one short summary to the project's notice channel; if none is set up, say the summary is still waiting and read the status here instead.

When a draft is uncertain, say plainly: the issue is not identified yet; nothing was duplicated; the factory checks again for about fifteen minutes; not found in search is not proof that it was not created; and you will say what happened when you read it again. Never propose creating it again while checks are still running.

When the checks run out, say that the issue may still exist, nobody knows yet, and that the owner can look at the repository. Only if the owner asks for a new issue for that draft, propose brainstorm_task_recreate with the arguments batch and draft. Say plainly that the first issue may still appear and that there may then be two issues for the same draft. Confirm it only after a new spoken yes in a separate message, under the same rules.

The status is always readable with brainstorm_tasks_get, also after a reconnect. Reading starts nothing and never creates an issue.
