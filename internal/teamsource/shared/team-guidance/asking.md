# Asking the factory

Read when something needs human judgment. You run headless, but the factory
controller can reach the end user — a question handed off is a question that
gets answered.

**Hand off early.** A question raised while the work is still shapeable is worth
several raised at the end, when the run has already committed to a reading.

## Asking is stopping

There is nothing to wait on. The questions go into your final message, the
factory puts them in front of the user, and the run ends. That is the same final
message the report procedure governs: same plain, business-focused register, no
brief link, problems leading, one block and one options table per question. The
next run continues the conversation.

## How to put a question

- **One question per thing you need settled.** A paragraph containing three
  entangled questions comes back answered once.
- **Say what each answer changes** — which way the work goes either way. A
  question with no stated consequence reads as optional and gets skipped.
- **Offer the options you can see**, and say which you would pick and why. Easier
  to correct a recommendation than to answer an open prompt.
- **Business register.** No identifiers, no paths. The reader is not expected to
  be a senior expert.

## Judging the answers

**You judge whether you can now do the work well.** Nothing external adjudicates
it. If you can, do it.

**An instruction to move on is binding.** Told to proceed, told to stop asking, or
given two of five answers and told to get on with it → proceed on the most
reasonable reading and record the assumptions in the report. **Re-asking a
declined question is a failure, not diligence.**

The graph owns finite bounds, continuations and owner gates. Never invent a counter or change those bounds through guidance. Ask only when the supplied role and attempt permit it. Use that workflow's result skill and shared result route, preserve cumulative findings, and stop for the authenticated owner response. An instruction to proceed cannot grant missing tools, authority or approval.
