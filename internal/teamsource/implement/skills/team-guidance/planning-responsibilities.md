# Planning, research and engineering boundaries

Research records request, observations, sources, assumptions, open questions and recommendations. Brief, technical and reference documents must trace to the same retained candidate. A search returning nothing proves no absence. Preserve prior applicable findings across passes. The selected research-evidence and result skills own documents and continuation; the graph owns publication and owner gates.

Plan retains approved intent, architecture, criteria, tasks and dependencies across iterations. Stories describe observable behavior for their audience; avoid implementation identifiers in story prose. Architecture investigates reuse and boundaries, interfaces, entities, invariants, failure behavior and permissions against current code. Acceptance maps every criterion to a task and future proof method; do not claim future checks were executed. Tasks have one responsible capability and explicit dependencies, with no cycles or dangling references. Revisions reopen affected approvals and retain unrelated decisions. Exact factory-authenticated owner promotion is required; drafting or input acknowledgment is never approval.

Implement consumes only the supplied frozen story and read-only completed dependencies. Work only on that story, keep file ownership isolated, verify every changed package completely and report actual failures. Complete each package run before repeating it. Use background logs for long runs; never stop someone else's process. Progress is advisory, not completion. The factory owns branch creation, save, merge, dispatch, retries and publication. No shell command or private report can replace its shared result route.

Validate assesses frozen criteria, retained snapshots and checks without executing new checks, editing, writing artifacts, delegation or mode changes. Missing evidence stays unverified, failing evidence stays failed, and advisory improvements alone do not block acceptance. The selected result contract owns the complete assessment and permission ceiling.

Sessions and manifests are supplied by the factory. Retain session boundaries, settled decisions, source attribution, amendment reasons and exact upstream references. Do not read session archives. Application context is a lookup reference, not a changelog; project constraints remain normative with stable identifiers. Story-file templates and operator dispatch scripts are not runtime authority.

For every criterion whose proof is not obviously available, retain an evidence inventory: criterion ID, proof method, source availability, version bounds and missing prerequisites. Consult the project's nested-agent evidence decision when applicable. Requirements records candidate obligations, story authoring carries them and acceptance checks completeness before freeze. Unsupported in-run nested observation is not evidence; externally captured fixtures establish only documented historical assertions. Unavailable proof remains an unsatisfied obligation.
