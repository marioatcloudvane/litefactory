# Research findings

_Technical detail behind [the brief](RESEARCH_BRIEF.md). Findings carry the source they rest on._

## f1

Install is source-build only: clone, go build into a versioned dir; docs state it is not a binary-release promise. No .github workflows and no git tags exist.

Evidence:

- `docs/getting-started/installation.md`
- `Makefile:4`

## f2

scripts/deploy-daemon.sh is the existing safe-deploy logic: clean worktree build, wait up to 300s for no pending/running graph attempts, stop, sqlite backup, keep .prev-<stamp> binary, rename swap (copying over a running binary makes macOS SIGKILL it), start, verify pid, print rollback. It is tied to the author's checkout, make, git and sqlite3.

Evidence:

- `scripts/deploy-daemon.sh:1`
- `scripts/deploy-daemon.sh:104`

## f3

Default team source is already a public raw GitHub URL to teams/teams.json on main; local paths and HTTPS URLs are accepted. Catalogue is generated by cmd/teamrelease. It follows the moving main branch, not a release tag.

Evidence:

- `internal/config/team_source.go:13`
- `teams/README.md:3`

## f4

Version is a build-time variable defaulting to dev, filled by Makefile via git describe; --version is handled by the router. Repo has no tags so builds report dev or a hash.

Evidence:

- `cmd/litefactory/main.go:28`
- `internal/cli/router.go:65`
- `Makefile:4`

## f5

init creates home, config, db and derives owner (gh) and bot identities; it does not check prerequisites and leaves the bot token to a pasted security add-generic-password command; daemon refuses to start until resolved.

Evidence:

- `internal/cli/cmd_init.go:22`
- `internal/cli/cmd_init.go:63`

## f6

A safe keychain writer already exists (security -i over stdin, keeps value out of argv) and a locked-keychain error is detected; init does not use it.

Evidence:

- `internal/secrets/keychain.go:98`
- `internal/secrets/secrets.go:131`

## f7

Command set has daemon run/start/stop/status and team install/clone/update/list/inspect/remove/link/unlink; no upgrade, uninstall or team add.

Evidence:

- `internal/cli/commands.go:11`
- `internal/cli/commands.go:36`

## f8

Getting-started docs tell users to run 'litefactory team add go-team', which does not exist; step 3 fails for new users.

Evidence:

- `docs/getting-started/README.md:22`

## f9

Documented upgrade is manual: build elsewhere, stop daemon, run init to migrate, start. Old binary retention does not guarantee database downgrade.

Evidence:

- `docs/getting-started/installation.md`
