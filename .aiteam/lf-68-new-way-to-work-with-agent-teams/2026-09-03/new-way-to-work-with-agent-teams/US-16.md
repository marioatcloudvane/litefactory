# US-16 — Gitignore the bookkeeping directory and protect it from accidental writes

> As a platform operator, I want litefactory's own bookkeeping files kept out of my repo's commit
> history and safe from being overwritten by anything other than the `team` commands themselves, so
> that installing a team doesn't pollute my repo with machine-local state or create a path other
> code could write to unexpectedly.

Delivers automatic `.gitignore` management for `.litefactory/` (US-9's bookkeeping directory) and a
runtime guard confirming every `team` write stays inside the paths this feature is allowed to touch.

## Why This Matters

`.litefactory/`'s contents — the lockfile and any US-13 overrides — describe the state of one
specific worktree's install, not something meant to be shared through git: per US-15, every worktree
of the same repo keeps its own independent copy, so committing it would create merge conflicts
between checkouts for no benefit and would leak local override paths into shared history. This story
also closes a defense-in-depth gap the SEC-7 override paperwork (US-1) opened: an approved exception
to litefactory's "never write outside your own paths" rule is only as safe as something that
actually checks the exception isn't exceeded, so this story adds that check in code, not only in the
recorded paperwork.

## Architecture Notes

- **Sequenced after US-15 deliberately:** because every worktree of a repo has its own
  `.litefactory/` (US-15), the ignore rule and the write guard both need to hold uniformly across
  every worktree an operator might run a `team` command from, not only the one where `.gitignore`
  happened to get touched first. This story reuses US-15's live worktree-discovery logic (T-41)
  rather than inventing a second way to enumerate worktrees, and confirms the rule is applied
  consistently in every worktree it runs against — that's the concrete reason this story could not
  land before US-15.
- `.gitignore` management: on first creation of `.litefactory/` in a worktree, append a
  `.litefactory/` line to that worktree's `.gitignore` if not already present; idempotent on repeat
  runs (never duplicates the line); if `.gitignore` doesn't exist yet, it is created.
- Extends the SEC-7 override's recorded scope: `.aiteam/AC_AMENDMENTS.md`'s entry from US-1 (T-34)
  recorded the initial five Owned Paths (`.aiteam/team.json`, `.aiteam/team.lock.json`, three
  harness dirs) — all five of which are now stale under the pure-index design, since the index is
  never written into the target repo at all. This story's amendment corrects the list to its actual
  current form: the three harness directories, plus `.litefactory/` (lockfile + overrides), plus any
  root files a renderer composes into per US-18. The two `.aiteam/team*.json` paths are removed from
  the list entirely, not carried forward as dead entries.
- Runtime guard: every write this feature performs (US-9's atomic-write engine, US-18's marker
  upsert) is checked, before the write lands, against the corrected Owned Paths list — a write
  targeting anything outside it is refused and reported as an internal error, not merely relied upon
  to never happen because the code was written correctly. This is the "protect the bookkeeping
  folder" half of this story: `.litefactory/` cannot be silently overwritten by a future change to
  the write path that forgets the constraint.
