*Original story body below, preserved for reference only — describes the REJECTED design.*

> As a platform operator, I want to know when litefactory's own definition of an agent has changed
> upstream, separately from whether my repo's own copy has drifted, so that I can tell "I edited
> this" apart from "the vendor changed this."

This story adds no new write behavior — it is a reporting distinction layered onto the drift
classification and update-reporting already built in US-10 and US-11.

## Why This Matters

An artifact can be perfectly in sync with what it was generated from and still be "out of date"
in a different sense: the fallback or organization-supplied definition it would be regenerated
from has since changed. Without this distinction, an operator has no way to know that running
`team update` will change something for a reason that has nothing to do with anything they did —
which matters when deciding whether an update is safe to run unattended or needs a careful look
first.

## Architecture Notes

- Delivered jointly by two other stories' tasks, not by any task of its own: US-10's `T-21`
  computes the `baseSourceHash` comparison that detects an upstream change, and US-11's `T-30`
  surfaces it in `team update`'s report output. This story owns the acceptance criteria for that
  behaviour, not its implementation.
- The distinction is deliberately orthogonal to drift class: an artifact can be `clean`
  (byte-for-byte matches what it was generated from) and simultaneously `upstream-changed` (the
  thing it was generated from has moved on).

## Tasks

*No dedicated tasks — this story's behaviour is delivered by US-10's T-21 (`baseSourceHash`

## Acceptance Criteria

| ID | Criterion |
|----|-----------|
| AC-1 | Changing an agent's definition in a lower layer (embedded or org) while the repo-local copy stays untouched causes `team status` to report `upstream-changed` for that artifact while its drift class remains `clean`. |
| AC-2 | `team update`'s report distinguishes an artifact it is rewriting because of an upstream change from one it is rewriting because it was merely stale or missing. |
