> As a platform operator, I want `litefactory team update` to bring my repo's generated files up
> to date with the current team definition — overwriting what's safe and flagging what a human
> touched — so that I never lose a hand-made customization silently.

This story implements the `team update` command against the drift classification built in US-10.

## Why This Matters

This is the command that makes the drift-detection design in US-10 actually useful: rather than
just reporting what's wrong, it acts on it — but only where it's safe to. A file nobody touched
gets refreshed automatically; a file someone deliberately hand-edited is left alone unless the
operator explicitly forces it, and a file that's both hand-edited *and* now conflicts with an
upstream change is flagged rather than silently merged, because there is no safe automatic way to
reconcile the two. Getting the boundary between "safe to overwrite" and "must be flagged" wrong in
either direction is exactly the failure mode this whole feature exists to prevent.

## Architecture Notes

- Per-drift-class behaviour is fully specified in `plan_brief.md`'s Shared Decisions §1 decision
  table — implement directly against it; this story does not re-derive per-class behaviour.
- `--prune` deletes **only** `orphan` artifacts (marker-bearing, absent from the lockfile); a
  `foreign` file is reported and never touched, under any flag combination, including `--force`.
  This split is the single sharpest data-loss hazard in the feature — do not relax it.
- Depends on US-4's scaffold (T-25), US-10's classification (T-21), and US-9's atomic-write layer
  (T-23) all already existing.

## Acceptance Criteria

| ID | Criterion |
|----|-----------|
| AC-1 | `team update` rewrites every clean or missing artifact, leaves every modified artifact untouched, and names each path it skipped. |
| AC-2 | When every artifact is modified, `team update` writes nothing and exits non-zero. |
| AC-3 | `team update --force` overwrites modified artifacts, naming each one it overwrote. |
| AC-4 | `team update --prune` deletes an orphan artifact; without `--prune` it is reported and left in place; a foreign file is never deleted by any flag. |
| AC-5 | `team update` rewrites lockfile entries only for the artifacts it actually wrote. |
| AC-6 | `team update --dry-run` prints the plan and leaves the filesystem, including the lockfile, fully unchanged. |
| AC-7 | A corrupt lockfile causes `team update` to fail without rewriting anything. |
