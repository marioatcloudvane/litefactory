# US-17 — Go-team bootstrap (first shipped team, dogfood deliverable)

> **PLACEHOLDER (2026-09-05).** This is a new story added by the 2026-09-05 narrow reconciliation
> pass, in response to the sponsor's fifth refinement ("the first shipped team must be a real
> go-team dogfood deliverable"). Full task breakdown, architecture notes, and acceptance criteria
> are **deferred to the follow-up planning pass** — this file exists only to hold the story's place
> in `plan_brief.md`'s Story Index and to record its scope and dependency now, before that detail
> is written.

> As litefactory's own maintainers, I want the first team shipped with this feature to be the real
> Go backend team litefactory itself uses, so that shipping this feature means immediately
> dogfooding it rather than shipping an empty framework with no real content behind it.

**Scope (one line):** author and ship, as the feature's first real content (not a fixture or a
toy example), a complete "go-team" index entry set — the actual agents this litefactory project
uses — renderable through every harness renderer landed by this plan.

**Depends on:** US-9 (`team add`, the write engine), and the three concrete renderers US-6
(Claude), US-7 (Codex), US-8 (opencode) — a go-team cannot be dogfooded until there is something
to add and something to render it with.

**Known open questions for the follow-up pass** (not resolved here): which existing agents (e.g.
`go-architect`, `go-implementation-engineer`, the various test engineers already in this
project's own roster) become the go-team's index entries; whether the go-team ships as the
embedded default team or as a separately fetched one; how much of this project's own
`.claude/agents/*.md` content can be reused verbatim as the markdown source the index points to,
versus needing rewriting to be harness-neutral.
