> As a platform operator, I want `litefactory team manage <agent> set model=x` (and its `get`/
> `unset` counterparts) to change one agent's parameter without hand-editing JSON, so that I can
> retune an agent's behaviour without understanding the whole config file's format.

This story implements the `team manage` command: a narrow, safe way to change a single agent
parameter in the repo-local config layer.

## Why This Matters

Not every change to a team should require understanding the full three-layer JSON schema —
sometimes an operator just wants to bump one agent's model or turn off one tool, quickly and
safely. This story gives them that, writing only to the repo's own config layer and never
touching a generated file directly, so the change goes through the same rendering and hashing
path as everything else the next time `team update` runs. It is deliberately narrow: it can only
ever change a parameter that a fixed, closed list says is safe to change this way — the plan
considered and rejected letting it touch arbitrary keys, because that would reopen every risk this
whole feature was built to close off.

## Architecture Notes

- `team manage` never re-renders or writes a generated artifact directly; it writes only
  `.aiteam/team.json` (the repo-local layer) and prints a hint to run `team update` afterward.
- Every settable parameter is screened before being written: a closed allowlist (US-14), range
  validation where applicable, `config.ContainsForbiddenFlag` (US-14's T-12), and
  `config.ClassifySecret` reused directly on the value. The allowlist and screening logic
  themselves are this story's own task (T-31); US-14 owns only the exported predicate it calls.
- A harness-scoped parameter set without `--harness` is a usage error naming the harnesses that
  need disambiguating — it never guesses which harness was meant.
- Depends on US-4's CLI scaffold (T-25) and US-14's exported `config.ContainsForbiddenFlag`
  (T-12).
- This story's test task (T-32) is the plan's final task: it depends on every other CLI command
  (`list`, `show`, `add`, `status`, `update`, `manage`) already being complete, since it covers
  CLI arity, flag precedence, and exit codes across all six.

## Acceptance Criteria

| ID | Criterion |
|----|-----------|
| AC-1 | `team manage <agent> set model=x` writes only `.aiteam/team.json`; every generated file is untouched; a following `get model` resolves to `x`, sourced from the repo-local layer. |
| AC-2 | `team manage <agent> unset model` removes the repo-local key; a following `get model` resolves back to whatever the next lower layer supplies. |
| AC-3 | `team manage <agent> set` on a harness-scoped parameter without `--harness` is a usage error naming the harnesses that need disambiguating. |
