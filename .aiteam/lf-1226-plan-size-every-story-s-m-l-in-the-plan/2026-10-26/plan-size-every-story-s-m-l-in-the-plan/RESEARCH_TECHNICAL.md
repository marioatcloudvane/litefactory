# Research findings

_Technical detail behind [the brief](RESEARCH_BRIEF.md). Findings carry the source they rest on._

## f1

A set entry carries only id, name, intent and optional depends_on. There is no size or reason field in the agent result type, the saved-state type, the revision hash, the owner table or the story issue shell.

Evidence:

- `internal/agentresult/plan_graph.go:70`
- `internal/planbrief/plan_set.go:22`
- `internal/planbrief/plan_set_proposal.go:38`
- `internal/planbrief/plan_set_proposal.go:102`

## f2

The set's revision is a hash of the marshalled entries. A new field marked omitempty leaves the revision of an already-proposed old set unchanged. Saved state is described as having optional members so older plans still load. This fits 'no backfill'.

Evidence:

- `internal/planbrief/plan_set_proposal.go:50`
- `internal/planbrief/plan_set.go:29`

## f3

Entries pass through a converter from the agent result to saved state. It copies four fields by name, so a new field must be added there or it is silently dropped. The story-stage prompt gets only name and intent as data. The story issue shell shows only name and intent.

Evidence:

- `internal/turn/plan_graph_set.go:32`
- `internal/turn/plan_graph_set.go:53`
- `internal/turn/plan_graph_issues.go:22`

## f4

The set limits (1 to 12 entries, unique ids and names, one-line intent of at most 280 characters, no cycles) are stated in the plan-set role. Shape validation is in the agent-result package. Both would need the size rules, such as allowed values and a reason length limit.

Evidence:

- `teams/source/base-team/plan/plan-set.md:49`
- `internal/agentresult/plan_graph.go:157`

## f5

S-01 exists only as text in the research ledger. Plan roles are told to let S-01 shape the set and each story, but no Go code reads or stores it. 'Starts from S-01 and refines it' is therefore a role instruction, not a data link.

Evidence:

- `teams/source/base-team/plan/plan-set.md:56`
- `teams/source/base-team/plan/plan-story.md:50`

## f6

The later stages are separate roles: story, technical and acceptance. The acceptance role assembles the final review and keeps Covers and Ruling notes. Depth-by-size would be instructions in those roles (few tasks and short criteria for S, normal for M, full for L). The requirement that coverage and proof links stay mandatory at every size is already in the role text and must be kept.

Evidence:

- `teams/source/base-team/plan/plan-acceptance.md:55`
- `teams/source/base-team/plan/plan-story.md:50`
