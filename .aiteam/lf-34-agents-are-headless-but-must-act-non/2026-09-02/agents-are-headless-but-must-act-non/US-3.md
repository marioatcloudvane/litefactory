# US-3 — implement-orchestrator.md: reword "pause and ask" sites

> As the implement-orchestrator, I want every place I currently say "pause and
> ask the user" reworded to match how I actually run — auto mode, no
> interactive asking — so that my own instructions stop contradicting my
> actual permissions.

This story rewords implement-orchestrator.md's several "pause and ask the
user" sites to headless framing, without changing Implement's behaviour: it
still never asks interactively.

## Why This Matters

Implement mode runs with no permission to ask questions at all — that gate is
enforced in code, not by convention, and this plan does not touch it. But the
orchestrator's own instructions currently tell it, in several places, to
"pause and ask the user" — wording that describes something the agent is
structurally incapable of doing. That mismatch is itself a source of
confusion: an agent reading contradictory instructions has to guess which one
is real. This story removes the contradiction by rewording every such site to
say what Implement actually does when it hits one of those situations: keep
going on the most reasonable reading, or — per US-4 — escalate by ending the
run with a report. This story must land after US-4, because several of its
sites are the exact points where US-4's new escalation path plugs in, and it
needs to know what that path is called before it can point at it.

## Architecture Notes

- **Must execute after US-4, in the same serialized chain** (US-4 → US-3 →
  US-5) against `implement-orchestrator.md` — do not edit this file
  concurrently with US-4 or US-5.
- Locate every edit site by its surrounding heading/anchor text, never by a
  line number cited during planning — US-4 inserts a new section ahead of
  several of these sites and shifts every line number below it.
- Four of the sites being reworded are also exactly four of US-4's escalation
  check points (Gate A, cycle exhaustion after the 2-cycle bug loop, the bug
  loop itself, and exit-time drift detection); reword each to point at the
  `## Escalating` section US-4 defines, rather than describing a live pause.
- The remaining sites (the preconditions statement near the top, and the
  Detour rule) are reworded to plain headless framing with no escalation
  pointer, since they are not check points.
- Two further sites were not named in the original scope list but read as
  live-dialogue scripts once the rest of the file changes: a line describing
  waiting on "the user reviews the escalation and confirms," and a TodoWrite
  example reading "blocked — waiting on user decision." Include both — leaving
  them makes the file self-contradictory against the rest of this story's own
  changes.
- Platform: none — no Go file in scope; Implement's actual asking permission
  is unchanged by this story.
- Risk: quote US-1's vocabulary and US-4's exact `## Escalating` heading;
  do not paraphrase either.
